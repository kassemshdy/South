Janoubona Code Audit

30 October 2026 · repository kassemshdy/South at develop-claude · FastAPI + SQLAlchemy + Postgres, React + Vite, MCP server · four read-only reviews plus a measured test-coverage run

The codebase is in good health where it matters most: every security rule the project set itself holds, errors are handled consistently, and there is no SQL injection or XSS path. The debt is structural. Routes do work that belongs in services, the business and service-provider halves of the app are copies of each other, and a handful of real defects in error reporting, caching and query loading are worth fixing first.

Scorecard

SecurityB+

All Security Musts hold. One high issue: Sentry can capture passwords from crashing requests.

Architecture & SOLIDC+

Layering leaks: 18 route modules query the DB, 87 commits in routes, 690-line main.py.

DRYC

Business and talent duplicate moderation, admin lists, image storage, serializers and admin pages.

Database & indexesB−

Core indexes exist; ~10 missing or unusable indexes, 4 redundant ones, N+1 on item images.

Caching & performanceC

Any write flushes the whole cache; invalidation is per container; no HTTP cache headers.

ScalabilityC

Backups and Telegram jobs run in the API process; pool can exhaust Postgres at 3 replicas.

TestsB

Backend 91% line+branch, MCP 79%, frontend unit 0%. Gaps: admin taxonomy, gallery routes, S3 backend.

Comments & docsB

Docstrings explain why. 8 stale comments; ~96 dated decision notes belong in an ADR log.

What is already good

Checked against the code, not assumed:

  • All 137 /api/admin/* routes go through require_admin; every admin write has a permissions.WRITES entry.
  • Every owner route is scoped to the signed-in owner; child ids are always filtered by their parent.
  • Private media folders are refused by the /media mount; storage keys are server-generated, path traversal is blocked.
  • No SQL built from f-strings; no dangerouslySetInnerHTML; CSV export guards formulas; JSON-LD is escaped.
  • Errors go through one hierarchy in core/errors.py; no bare HTTPException.
  • TypeScript is strict with effectively zero any; data fetching is all react-query with sensible stale times.
  • Storage is a clean strategy pattern (local disk / S3) behind one factory.

Remediation roadmap

Every item is a small pull request into develop-claude, green on all four CI jobs, then released. Refactors change no test expectations; fixes land with a test that fails before and passes after.

Phase 0 · days

Security and correctness

  • Sentry locals off, secret fields, frontend breadcrumb scrub
  • SEO regex crash
  • Image pixel cap; body size cap; FastAPI/Starlette upgrade
  • Covers: store new before deleting old
  • SECRET_KEY length, staging headers, CORS credentials, health endpoint
  • Per-IP login limit; purge and lock rate-limit events
Phase 1 · ~1 week

Database and performance

  • Fix N+1 on item images; summary vs detail loaders
  • One concurrent index migration (8 add, 5 drop)
  • Product search on search_text; date filter rewrite
  • Targeted cache invalidation, DB-backed version, HTTP cache headers
  • Light search suggest; count(*) over()
Phase 2 · ~1 week

Tests

  • Untested routes: taxonomy, ID back, reorders, queues
  • Unit tests for pure logic
  • vitest setup + frontend logic tests in CI
  • E2E: approve flow, item editor, taxonomy
  • Coverage report and single-head check in CI
Phase 3 · 2-3 weeks

Refactors (DRY, SOLID)

  • ListingImageService + CoverImageService; DI providers
  • Listing base repository; one moderation service; serializers by domain
  • Repositories/services for workshops, jobs, reels, activities, pages
  • Services own commits
  • Split main.py and telegram_archive.py
  • Frontend: lazy routes, shared admin pages, split ItemManager
Phase 4 · ~1 week

Scalability

  • Backups and Telegram jobs to a worker; durable outbox
  • Pool sizing or PgBouncer; no session during image work
  • Buffered view counter
  • Migration timeouts; non-root image; locked dependencies
Phase 5 · ongoing

Comments and docs

  • docs/decisions/ for dated decisions
  • Fix 8 stale comments
  • Docstrings on long functions
  • Delete dead code and unused i18n keys

QuestionTrade-off
Keep must_change_password as a kill switch?Kept on purpose today; removing it simplifies auth code and one test.
Shorter admin session (e.g. 12 hours)?Limits the damage of a stolen token; staff sign in more often.
